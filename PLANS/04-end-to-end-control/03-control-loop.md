# 04.03 — Control loop

- **Objective:** Connect validated observations → tunneled inference → buffered actions → MuJoCo using stock OpenPI runtime pieces.
- **Inputs/prerequisites:** Ready server/tunnel; buffer/contract tests; selected profile.
- **Implementation tasks:** Construct `AlohaSimEnvironment`; bounded WebSocket client at `127.0.0.1:<validated-port>`; verify handshake profile/config/checkpoint/SHA before action execution; use buffered policy + `PolicyAgent`. Patch shared `Runtime` minimally to use `time.monotonic`, increment/check step counts without the current `max+1` error, invoke episode end exactly once from `finally`, and allow this simulation runner to skip the unconditional final reset. Extend the sim environment so its first reset passes the constructor seed verbatim to Gym (only later resets derive RNG seeds), and add read-only last reward/info/result plus `close()`; make `VideoSaver` idempotently write available frames through a temporary file and atomic rename whether the episode completed or was interrupted, while the terminal manifest labels complete/partial. Run one fresh environment per episode using seed `ALOHA_SEED + episode_index` after range validation; `finally` closes policy/socket/worker and environment and preserves the manifest even if video encoding fails.
- **Files expected to change:** `tools/remote_aloha/run.py`, `scripts/run_aloha.sh`, config, `Makefile`, `packages/openpi-client/src/openpi_client/runtime/runtime.py` plus focused test, `examples/aloha_sim/{env,saver}.py` plus focused tests.
- **Validation:** One short controlled run with exact requested actions (catches the stock max+1 bug); assert the first Gym reset receives constructor seeds 0/1/2 verbatim and any later reset is separately logged; Ctrl+C during inference and during video write; connection loss; complete episode; finalizer idempotence; no unconditional reset counted as an episode; no orphan sim/client worker.
- **Acceptance:** Correct data flow with no schema/network termination; exact full episode runs; selected server identity matches; complete or explicitly partial video/result manifest saved; process exits in bounded time and releases local resources.
- **Planned commits:** `fix(runtime): correct episode accounting and finalization`; `feat(runtime): connect ALOHA simulation to remote policy`.
- **Actual findings:** Stock ALOHA main exposes host/port/task/seed/horizon/display but only one episode and no profile/telemetry. Stock environment derives even its first Gym seed from an RNG. Stock Runtime supports episode count/max steps, but shortened runs currently execute `max_episode_steps + 1` actions, timing uses the wall clock, subscribers finalize only on normal completion, and a final reset always runs.
- **Remaining blockers:** End-to-end hardware access.
- **Completion status:** Planned.
