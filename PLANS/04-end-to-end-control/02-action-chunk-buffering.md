# 04.02 — Action chunk buffering

- **Objective:** Decouple chunk inference latency from most 20 ms simulation steps using minimal stdlib machinery.
- **Inputs/prerequisites:** Valid observation/action contracts; measured warmed p95 latency; initial execution horizon 10 and prefetch threshold 5.
- **Implementation tasks:** Validate `1 <= ALOHA_PREFETCH_STEPS < ALOHA_ACTION_HORIZON <= 50`; use `collections.deque` for validated single actions; validate `(50,14)` input and retain at most `actions[elapsed_steps:elapsed_steps + ALOHA_ACTION_HORIZON]` (the first request has `elapsed_steps=0`), exposing remaining/pop/replace/clear without repeating the last action. In a thin `BasePolicy` wrapper keep one `ThreadPoolExecutor` future tagged with episode generation and observation step. Start prefetch at the threshold; while it runs, consume the current buffer. On result, reject old-generation data, compute elapsed simulation steps, and atomically replace any old remainder with only that bounded fresh slice; never append a late chunk. If the slice is empty, re-infer from the latest observation. On underrun wait without stepping and emit duration. `reset()` increments the generation and clears buffered/completed results; an idle reset keeps the healthy transport (including the Runtime's first pre-episode reset). If inference is running, reset closes the socket to unblock/drain it, recreates the client, and revalidates profile/config/checkpoint/SHA before returning. Terminal idempotent `close()` permanently closes transport/worker and ignores late results.
- **Files expected to change:** `tools/remote_aloha/action_buffer.py`, `tools/remote_aloha/buffered_policy.py`, `tests/test_action_buffer.py`, config.
- **Validation:** FIFO order; `elapsed=0,horizon=10` retains indices 0–9; `elapsed=5,horizon=10` retains indices 5–14; `elapsed>=50` re-infers; horizon/threshold validation; short/invalid chunk; atomic replacement; first Runtime reset after construction then inference; idle reset then inference on the same healthy connection; reset during a request followed by reconnect/identity check; late prior-generation result; one request in flight; ready-before-empty and underrun paths; inference error propagation; finite terminal close.
- **Acceptance:** Exactly one action `(14,)` per sim step; maximum one in-flight request; no prior-generation, elapsed-leading, appended-late, or repeated action; first/underrun waits observable; no new dependency.
- **Planned commit:** `feat(runtime): execute prefetched action chunks`.
- **Actual findings:** Upstream `ActionChunkBroker` is synchronous and waits until all 10 actions are exhausted before requesting again, so it cannot maintain wall-clock 50 Hz across inference boundaries. Its slicing semantics remain the reference.
- **Remaining blockers:** Tune threshold/horizon only from warmed Mac-client end-to-end p95 through the SSH tunnel (serialization + network/tunnel + server + response decoding), not WSL-local or server-only `infer_ms`. Require `p95 request latency + margin < prefetch_steps × 20 ms` to claim uninterrupted 50 Hz; otherwise raise the values up to the 50-action model ceiling or report measured underruns without the claim.
- **Completion status:** Planned.

`ponytail:` one worker and one in-flight chunk are the intentional ceiling; add a more complex scheduler only if measured underruns persist after threshold tuning.
