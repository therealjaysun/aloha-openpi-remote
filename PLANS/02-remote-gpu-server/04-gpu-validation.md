# 02.04 — GPU validation

- **Objective:** Prove each selected policy performs real RTX 3090 inference rather than merely starting.
- **Inputs/prerequisites:** Ready server; WSL-local OpenPI client; verified available outer process-deadline tool (normally GNU `timeout`); GPU metrics access.
- **Implementation tasks:** Capture sanitized `nvidia-smi` baseline; run every pre-phase-03 WSL-local smoke invocation under a validated finite outer process deadline with TERM then bounded KILL fallback and record timeout exits, so the stock client cannot hang phase 02; time request 1 as cold, then issue two warmups and measured warmed inferences per profile; validate handshake identity, backend/device, response dtype, and finite `(50,14)` actions; capture process GPU memory/utilization before/during; record cold/warm latency and checkpoint/profile/SHA; detect CPU fallback and fail. Preserve the stock full-FP32 converter and JAX runtime as defaults. Add the opt-in `partial-bfloat16` recovery mode from [`LOW_MEMORY_CONVERSION_OPTIONS.md`](LOW_MEMORY_CONVERSION_OPTIONS.md): prove one BF16 leaf against FP32→BF16, consume every stored source leaf exactly once, copy each mapped target once into a GPU-resident model, release each source leaf, save standard 1 GB shards into an owned temporary directory, copy the checkpoint's own assets, strict-load accounting only for the proven tied alias, and publish atomically. Add explicit `OPENPI_POLICY_BACKEND=jax|pytorch` selection: JAX uses the pinned original checkpoint; PyTorch requires the profile-matched local converted directory, rejects missing/mismatched artifacts without fallback, disables optional `torch.compile` autotuning for the memory-bounded demo, omits JAX-only gates, verifies Torch CUDA/RTX placement, and reports backend/device metadata. Phase 03 replaces the coarse inference guard with per-stage client deadlines/close.
- **Files expected to change:** `examples/convert_jax_model_to_pytorch.py`, `src/openpi/policies/policy_config.py`, `src/openpi/models/model.py`, `scripts/convert_policy_checkpoint.sh`, `scripts/start_policy_server.sh`, `tools/remote_aloha/config.py`, `tools/remote_aloha/remote.py`, `.env.example`, `Makefile`, focused tests, and evidence references in plans/docs (raw output ignored).
- **Validation:** Default converter and JAX runtime behavior remain unchanged; focused local tests cover opt-in conversion, explicit backend routing, rejection without a matching artifact, finite deadlines, locks, temporary ownership, sharded loading, and backend/device metadata; the PC proof checks representative BF16 value equivalence; full conversion checks exact source/target counts, keys, shapes, dtypes, single writes, assets, shard index/hash, and fresh-model loading; profile-specific PyTorch smoke inference remains the final acceptance gate. Because WSL `nvidia-smi --query-compute-apps` did not expose the Torch server's Linux PID, PyTorch acceptance instead requires handshake proof that the loaded model itself is on `cuda:0`, 3090 sampling during inference, WSL host-RSS sampling, immediate owned-process verification, and survival in a second SSH session; JAX retains per-process `nvidia-smi` attribution.
- **Acceptance:** Both profiles allocate RTX 3090 memory and return valid actions; π₀.₅ task success is not inferred from shape validity; evidence is sanitized.
- **Planned commit:** `feat(remote): add bounded PyTorch recovery path`.
- **Actual findings:** The WSL-local smoke client implements one cold request, two warmups, and one measured warmed request for either fixed profile; validates exact safe metadata, finite floating `(50,14)` actions, source SHA, and GPU identity. RTX 3090 detection, locked setup, π₀ checkpoint loading, server health, cross-session survival, GPU sampling, and owned-process cleanup passed. JAX first inference OOMed at 75%, 90%, and 95% preallocation, with on-demand allocation, with the documented minimum-footprint allocator, and after fully masked camera views were omitted at 90% and 95%. No valid action or latency was produced. The pinned official PyTorch converter expands weights to float32, creates a second model, and materializes serialization bytes; it and a BF16 restore probe were kernel-OOM-killed under roughly 11.7 GiB WSL RAM. No drop-in OpenPI-format PyTorch checkpoint was found in the queried official OpenPI bucket as of 2026-08-27.
- **Remaining blockers:** Run the locally validated explicit-backend candidate through the bounded opt-in partial-BF16 experiment on the current PC for π₀. If its proof, restore, mapping, serialization, fresh-model load, or inference fails, stop and retain CPU Ubuntu 22.04 with ≥32 GiB RAM available to the process and ≥60 GiB free disk (64 GB total host RAM preferred for Windows/WSL) as the supported conversion fallback. Do not convert π₀.₅ until π₀ converts, fresh-loads, and returns finite RTX actions. Conversion is not acceptance; both profile smokes must return finite actions. Do not add undocumented or experimental JAX allocator flags. Mac-through-tunnel validation remains Phase 03.
- **Completion status:** Blocked by the current GPU/system-memory combination after the selected documented non-experimental allocator tests; π₀.₅ remains untested.
