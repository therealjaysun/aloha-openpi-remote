# 04.02 — Action chunk buffering

- **Objective:** Decouple chunk inference latency from most 20 ms simulation steps using minimal stdlib machinery.
- **Inputs/prerequisites:** Valid observation/action contracts; measured Phase 03 warmed latency; initial execution horizon 30 and prefetch threshold 25.
- **Implementation tasks:** Validate `1 <= ALOHA_PREFETCH_STEPS < ALOHA_ACTION_HORIZON <= 50`; use `collections.deque` for validated single actions; validate `(50,14)` input and retain at most `actions[elapsed_steps:elapsed_steps + ALOHA_ACTION_HORIZON]`. Keep one `ThreadPoolExecutor` future tagged with its observation step. Start prefetch at the threshold; while it runs, consume the current buffer. On result, compute elapsed successful simulation steps and atomically replace any old remainder with only that bounded fresh slice; never append a late chunk. If the slice is empty, re-infer from the latest observation. On underrun wait without stepping and emit duration. Terminal idempotent `close()` closes the socket to unblock inference and joins the sole worker. A fresh client/buffer per episode removes cross-episode reset and generation state.
- **Files expected to change:** `tools/remote_aloha/action_buffer.py`, `tools/remote_aloha/buffered_policy.py`, `tests/test_action_buffer.py`, config.
- **Validation:** FIFO order; `elapsed=0,horizon=10` retains indices 0–9; `elapsed=5,horizon=10` retains indices 5–14; `elapsed>=50` re-infers; horizon/threshold validation; short/invalid chunk; atomic replacement; one request in flight; ready-before-empty and underrun paths; inference error propagation; close unblocks and joins an in-flight request.
- **Acceptance:** Exactly one action `(14,)` per sim step; maximum one in-flight request; no prior-generation, elapsed-leading, appended-late, or repeated action; first/underrun waits observable; no new dependency.
- **Planned commit:** `feat(runtime): execute prefetched action chunks`.
- **Actual findings:** Upstream `ActionChunkBroker` is synchronous and waits until all 10 actions are exhausted before requesting again. The new one-worker buffer passed all six episodes without stale/repeated actions or fatal underrun, but warmed Mac-client request p95 was 451.71–612.38 ms and per-episode underruns were 0–2. The 500 ms prefetch budget therefore did not qualify with the 100 ms margin, and active control measured 45.44–47.09 Hz.
- **Remaining blockers:** None for Phase 04 infrastructure acceptance. Do not claim uninterrupted 50 Hz from this evidence; further performance work needs measured inference-tail reduction or a model/server contract beyond one 50-action sequential chunk, not an unproven threshold change.
- **Completion status:** Complete with the measured cadence limitation explicitly retained.

`ponytail:` one worker and one in-flight chunk are the intentional ceiling; add concurrency only if Phase 05 proves the server can safely order it and measured tail latency materially improves.
